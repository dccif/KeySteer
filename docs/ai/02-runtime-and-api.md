# 运行时与公共 API

```text
TOML → ConfigFile → app::configuration → RuntimePlan → Engine
                                                     ↕ ModeEvent / Command
                                                  Mode / Plugin
Engine → Backend → OS
Mode → HostContext::present(View) → presentation → OverlayScene
```

## 所有权与入口

`src/app/runtime/mod.rs` 装配 Engine；`registry.rs` 管模式和路由，`input_state.rs` 管输入配对，`scheduler.rs` 管待执行任务，`overlay_coordinator.rs` 管呈现，`commands.rs` 解释命令。这些文件位于 `src/app/runtime/`。

跨层词汇在 `src/api/backend.rs`、`src/api/command.rs`；原生对象不进入模式。

Engine 使用单一派发入口完成 owner 查找、上下文装配和命令执行。帧和指针通知不含可复用缓冲，继续调用借用 `handle`；其余事件交给 `Mode::handle_owned`，默认实现仍调用原有借用处理器。窗口等拥有消费实现的模式直接接管结果、按键和焦点事件，不再先借用后克隆回拥有值。帮助缓存仍在原有输入／结果边界失效，帧和指针通知不额外清空缓存。

`OverlayScene.retained` 描述不可变的背景图元和可省略的普通标签槽位，前景仍使用常规 labels／shapes；它不携带 Hint 状态或原生资源。`materialized()` 提供完整场景兼容视图，原生后端可按共享身份复用背景。会话的 `HintSceneCache` 只拥有已解析样式、场景及必要的槽位索引；完整目标顺序、保持目标顺序的过滤结果和唯一标签不另建索引，分别使用直接位置或已有 hints 的二分定位，并核对标签身份；搜索重叠场景在实际按层序输出时记录槽位整数，复用容量并跳过后续文字建表；首次普通重叠场景提交后，Mode 向 Presenter 借用传递现有 HintContent 和 VisualLayerPlan；Presenter 每份最多处理指定数量的源标签，利用已经排好层序的场景填充整数槽位，不重复排序或建立文字哈希表。未准备的成员保留即时查找回退，Mode 负责内容／层序变化与退出失效。

连续滚动通过 `Command::ScrollFrame` / `Backend::scroll_frame` 保留取消身份和每帧距离，runtime 在提交前应用滚动反向设置；离散 `Scroll` 不可替换。原生执行与积压策略由共享滚动执行器负责，见[平台后端](06-platform-backends.md)。

## 关键语义

- 同步 Hook 先取得 consume/forward 决定，再执行可能耗时的动作；不得让 Hook 与 Engine 互相等待。
- 后端可通过 `Backend::run_event_loop` 驱动有界、非阻塞的引擎回合；不支持时使用普通 poll 循环。原生驱动必须在引擎／后端借用之外派发系统事件，回调不能重入或逃逸。输入、帧、异步结果和定时任务共用原有路由，菜单跟踪不暂停模式、不重启或清空选择。原生回合返回终态前执行统一清理，让 AppKit 的 TerminateLater 嵌套循环能收到退出确认；原生驱动自身在回合外失败时，返回引擎清理。驱动保留展开所需的菜单对象，不允许清理期间重入引擎。
- 没有定时任务时 `Duration::MAX` 表示无截止时间等待，由原生事件立即唤醒，不保留引擎心跳；有任务时使用最近的真实截止时间。后端不能把该哨兵直接加到 `Instant`；通知不可用时的降级轮询、尚未完成的原生确认及重试由后端提供期限。
- Down/Up 保持配对；held release 交给按下时的 owner，不在松键时重新解释绑定。
- 退出、暂停、捕获丢失及失败恢复都要清理合成保持状态；先尽力完成恢复，再统一记录错误。
- 当前事件处理已请求退出时，同回合跳过后续到期任务，避免定时回调和延迟动作继续产生工作；普通循环与原生驱动共用此入口。引擎结束运行时先通过 `Backend::stop_input_capture` 非阻塞地停止同步输入捕获，再释放合成保持、取消会话和等待配置／工作区 I/O。保存完成后才调用最终 `shutdown`，避免提前确认系统退出；清理错误仍汇总，不能跳过后续资源释放。
- 成功的合成 click/double-click 只发一次语义 `Clicked`；物理点击和 press/release/toggle 不发。
- 异步结果按请求、会话和 owner 归属处理；迟到结果不能恢复已经退出的交互。
- 输入优先，但后台通知不能无限推迟就绪帧；可靠完成事件保序，只有明确可替换的状态通知允许合并。

模式切换见 [生命周期](04-modes-and-lifecycle.md)，配置替换见 [配置](03-configuration.md)。

Text Input 默认只消费显式返回绑定，其余输入保持原始 Down/Up 透传；不默认继承或临时借用 Normal，避免 Primary 在 macOS 映射为 Cmd 时接管 Cmd+A/C/V 等编辑快捷键。临时模式仍支持显式配置，沿用公共路由、owner 和释放规则，不为系统快捷键新增特判或逐项白名单。

UI 扫描的 UiScanActivationExpected 按 scan owner 路由，必须在对应原生焦点通知前送到模式，防止一次主动激活触发重复扫描。范围选择与跨平台激活策略见 [UI 扫描](05-ui-scanning.md)。

UIHint live TextPrompt 仅建立共享输入路由，不调用原生 request_text_prompt。runtime 在任何编辑、剪贴板和绘制工作前确认按键处置；TextInserted／TextEdit／TextPasted 交给 Mode，原生备注仍走原有异步协议。 未被编辑／复制／点位快捷键处理的修饰键，按 Mode 的 claims_key 交还给输入 owner；松键也交还，避免会话内状态变化丢失释放。搜索期间保留配置的重叠换层键，当前预览高亮仍置顶。 已解析的点位／换层事件直接复用，外层不重复构造按键集合或匹配复制快捷键；松键仅使用已有 tap／held 记录，组合键匹配只在按下时执行。

模式自有编辑面板通过 `Mode::keyboard_prompt_supported` 声明稳定能力，Registry 在注册／替换实例时采样并缓存；只有声明支持的实例才逐键查询活动状态与上下文绑定，不能为多选输入给普通模式增加动态面板调用。临时层未启用时保留面板上下文绑定；启用时先查当前模式自身依赖激活键的显式组合键，再用剔除实际激活键后的按键依次查临时层、当前层；跨层不比较组合长度，继承不能重新带回已消耗的激活键。每层先查自身，再查安装路由时按配置顺序深度优先展开并去重的继承清单；首个匹配即终止，包括 `none`，不会因禁用而继续查后续继承来源或另一层。绑定与 passthrough 都以完成键相符、组合所需成员均已按下为匹配条件，不要求覆盖所有已按下键；既有严格修饰键规则仍由键表执行。`none` 只阻断绑定回退，原始输入与系统透传仍由模式处理。不被 live 编辑器、复制或点位处理提前消费，Window 不另设优先级。显式 passthrough 直接查当前层并保留当前面板操作。临时层反向继承当前模式时，路由安装还预编译当前模式接管原始按键后的查找顺序：只跳过该模式的继承分支，其他分支及其共享祖先仍可命中。查找顺序只保存模式 ID，后注册的模式与应用覆盖继续使用当前键表。窗口固定帮助在建表时按配置组合的身份检查遮蔽，保持组合清单独立于实时按键状态。松开激活键统一释放借用 owner 的保持动作，保留原模式实例与选择；切层键先松开或切换模式时，序列绑定沿原绑定逐个释放其中的持续动作，不把整个序列直接交给 Mode，也不重新查询当前层的同名按键。文字选择帮助随有效临时层显示对应绑定。

显式面板 Send 绑定可通过 `Mode::keyboard_prompt_edit` 转为 `ModeEvent::TextEdit`，由模式解释光标／选区；不向前台窗口注入这些编辑键。普通模式继续跳过动态面板查询。

输入会话完成（含取消、错误）须先关闭字符捕获，再移除 owner 并派发结果；关闭命令重复执行也要确保捕获关闭。旧请求的迟到结果不得关闭新会话，live 搜索结束不进入原生窗口的焦点恢复流程。

原生布局保存备注期间冻结模式的焦点快照，输入法辅助进程、候选窗口及应用重新激活不能取消编辑；会话由明确的提交／取消、模式退出或暂停收尾。普通按键和输入法切换快捷键继续转发给原生编辑器。
原生备注编辑不逐键重建窗口帮助覆盖层。公共 disposition mailbox 的 wait_with_fallback 接收原生实际超时回退决定：Windows 键盘／鼠标按键按已有按下配对状态提供 Forward 或 Consume，macOS 键盘提供 Forward（鼠标按键仍走严格等待）。明确为 Forward 的超时可接受一次迟到的同代 Forward 确认，不触发全局恢复；Consume／Defer、关闭后的确认及原生回退为 Consume 的事件仍严格拒绝。只保留最近一次可确认超时，不建立无界历史或延长按键等待。

Live 搜索点位快捷键在复制／编辑优先级之后处理，轻触键在其他按键按下时撤销。调整期间多点切换经 ModeEvent::CyclePointTarget 派发并停止当前移动，方向／速度从已有 Normal 键表解析，held release 留在同一搜索 owner；匹配复制和退出键时忽略正在保持的移动键，避免按住方向无法退出。关闭、配置替换和输入恢复同时清除点位路由、采样 owner 和帧时钟。

点位调整期间，复制继续保留信息源直到 TextCopied 成功。普通操作绑定在按键处置确认后先接受并关闭搜索，再走既有动作／长按与 Down/Up 配对路径；移动与速度控制仍留在点位状态。

Live 搜索的编辑、复制和点位快捷键统一匹配配置解析出的 `KeyChord`，允许无关查询字符的物理按键交叠，不依赖默认键名。单键、标点、功能键、配置别名及多键组合沿用同一规则；组合内全部成员及修饰键集合仍须匹配，显式左右侧修饰键不能互换，多字母组合不能降为单键。该容错不扩展到普通模式的命令匹配。

模式可通过 `RequestModeList` 取得按使用次数排序的注册模式快照，由 `ModeList` 所有权转移交付。面板窗口定位通过 `RequestPanelWindowBounds`／`PanelWindowBounds` 异步往返；Engine 将模式请求号映射为跨模式及重载不重复的原生序号，并核对焦点进程，先提交待绘制面板再查询。错误统一记录一次，模式仍使用屏幕回退。

文字选择通过既有 live TextPrompt 收取编辑事件。未借用临时层时，处理顺序为模式的 `keyboard_prompt_binding`、面板复制／编辑绑定、普通字符；模式绑定先复用公共 `literal_character_key` 与预编译字符键索引匹配系统实际产生的字符，再匹配物理键组合，保留真实物理键的处置与释放。不硬编码问号、键盘布局或 key_help 动作；未绑定／禁用的字符仍按模式策略输入。默认细分用独立于 Primary 的 `Alt+C`（macOS Option+C），复制绑定默认合写为 `"mod+c enter" = "text_copy"`（Windows/Linux Ctrl+C，macOS Command+C），不依赖可配置 Primary。复制键由 `text_select.bindings` 修改，始终优先复制面板勾选文字，不依赖输入内容／选区。该模式不接入共享编辑器的 Copy／Cut；`ctrl+x = text_clear_input` 清空整个查询和光标选区，保留当前层级与细分层已确认的勾选，不操作剪贴板。模式可在输入非空时让 Backspace 回到编辑器。`key_help` 对文字选择的 live prompt 使用相同的上下文绑定判断，显示当前有效的控制与编辑键，并合并模式提供的首层重叠换层键；修饰键仍走公共 live prompt owner 路由。其他文本面板保留原有帮助显示规则。窗口恢复的翻页帮助根据实际绑定与页数动态生成，不写死 PageUp/PageDown。

模式可为当前绑定提供上下文按键帮助标签，不改变绑定本身；区域 UIHint 将默认 Tab 的帮助显示为 `previous_level`，普通 UIHint 仍显示 `reopen_selection`。

`HintView.highlighted_hint` 允许文字选择在没有四栏信息面板时指定当前预览标签；与 UIHint 从信息面板／点位推导的标签共用置顶、高亮样式及保留场景槽位替换，不另建标签绘制路径。

系统分词使用 `api/text_select.rs` 的 UTF-8 范围协议。执行 `SegmentText` 前先提交批次中已有的等待场景，再向后端交付工作；不能让场景合并延后首屏至原生任务启动之后。运行时以单调全局 id 映射模式局部请求 id，退出时取消工作并移除所有权，旧结果不能投递到重入后的会话。后端不可用时交付空分词结果，让模式按字符边界回退；引擎不等待系统分词线程，回退的最终场景仍在等待场景之后提交。
