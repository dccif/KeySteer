# UI 扫描

链路：Mode 发 `ScanUi` → Backend 调度原生扫描 → 按来源提交就绪数据 → 复用的单写者融合线程 → 合并结果邮箱 → `UiScanned` → Hint 会话更新。

## 入口

- 协议：`src/api/command.rs`；消费端：`src/modes/hint/`。
- Windows：`src/platform/windows/accessibility.rs`、`src/platform/windows/ui_scan.rs`、`src/platform/windows/vision/`。
- macOS：`src/platform/macos/accessibility/mod.rs`、`src/platform/macos/ui_scan.rs`、`src/platform/macos/scan_workers.rs`、`src/platform/macos/vision/mod.rs`、`src/platform/macos/vision/vision_ocr_process.h`。
- 共享调度与算法：`src/platform/common/scan_fusion.rs`、`src/platform/common/scan_progress.rs`、`src/platform/common/scan_mailbox.rs`、`src/platform/common/scan_accumulator.rs`、`src/platform/common/image_tiles.rs`、`src/platform/common/scan_priority.rs`、`src/platform/common/scan_reuse/`、`src/platform/common/spatial_index.rs`、`src/platform/common/contour/`。

## 必须保持

- 扫描异步、可按 scan id 取消，流式交付 Partial；Engine 不等待完整扫描。
- 结果验证 scan id 和目标上下文；旧请求不能覆盖新会话。
- 终态与数据分开理解：超时不等于清空已有目标；重扫和退出清理旧会话资源。
- 重扫复用退出的会话清理和后端取消入口，再提交新 generation；连续重扫只保留最新待执行请求，取消旧活动请求不能失效已排队的新一代。两端在交付终态、移除扫描归属前也通过同一入口取消剩余原生任务，避免 Windows 可选 UIA 预览或 macOS 超时原生调用遗漏取消；邮箱已消费终态不能成为跳过任务取消的理由。
- 目标数量及整屏扫描的窗口数量动态增长，不设固定条数上限；遍历保留期限、深度与 generation 检查，图像和在途原生工作仍有资源边界。取消不能只取消显示而让旧任务无限运行。
- 去重及多来源融合保持稳定语义，不依赖哈希迭代顺序。
- AX／UIA 原生控件的前置去重共用 `spatial_index::NativeTargetDeduper`：名称和角色必须一致，矩形还须满足公共融合层相同的 IoU 判定及 `merge_iou_threshold`；8 个后端坐标单位的网格仅缩小候选范围，中心接近不能单独判重，较大偏移仍交给完整融合索引。名称／角色编号参与网格键，新名称跳过候选查询，避免同位置不同名称的目标互相遍历；短名称用已有的 `SmolStr` 内联保存，首个矩形直接随名称／角色保存；只有同身份的后续矩形进入网格及附加矩形数组，避免为唯一名称创建空间桶。首个矩形仍受同一网格邻域限制，较大偏移不会因这项存储合并而提前判重。macOS 不再仅凭半点量化矩形提前丢弃目标，名称在判重前读取，因此重复 AX 节点可能增加名称查询；名称按既有顺序惰性读取，取消及期限检查仍覆盖读取前后。Windows 同样保留原生线程和上下文检查。该前置过滤与跨来源优先级融合职责不同，不查询额外原生身份，也不保存整树快照。
- `ScanMailbox` 在合并增量时，目标及撤销缓冲为空则直接接管传入存储，已有内容才追加；撤销仍先移除尚未交付的旧目标，保留增量顺序和代次隔离。
- 每次融合交付一份目标数组和撤销数组，二者作为同一增量发布，不增加多批次外层容器。启用 OCR 的 Hybrid／Vision 扫描保持来源内顺序和原有去重规则融合所有结果，但轮廓碎片及 macOS 原生矩形暂存于现有搜索目标缓存，仅增加对应的待发布标记；原生语义、OCR 文字和轮廓图片流式显示。隐藏候选的撤销和元数据更新不发给 Hint；共享 `scan_progress` 跟踪所有启用来源尚未完成的区域，区域稳定后即可按 Partial 发布剩余候选及其最新名称。原生层在开始交付前声明完整区域计划，窗口／分块完成通知与结果进入同一来源 FIFO，不能越过尚未融合的目标。Windows UIA 主遍历及可选预览分别占有窗口区域；macOS AX 按窗口交付进度，Quartz 计划覆盖 AX 匹配的几何容差；系统 OCR 用含 halo 的分块区域，轮廓和原生矩形按帧。候选必须与所有来源的未完成区域分离；OCR 还对相接的未完成块及同来源活动文字做保守包围闭包，避免后续接缝拼接扩展到已发布区域。未声明、异常或无法验证的区域保持等待；有效终态补入剩余候选，失败／超时也保留已有候选，取消、上下文变化及旧代次直接丢弃。纯 Contour 或关闭 OCR 的 Vision 保持立即显示。不增加固定等待、来源计算屏障、第二份目标缓存或截图持有；终态先发布，随后在同一融合线程当前回合随任务释放扫描证据，不延迟到下一轮扫描。后到 OCR 对已显示目标的元数据替换仍直接交付，不反查空间索引或重复比较完整目标；图片名称仅在变化时复制。
- 候选撤销时同时清除其待发布标记，避免已无待发布目标时继续准备区域闭包；启用延后发布时原位筛选撤销数组，仅交付已发布目标，剩余数量不足容量四分之一时收缩，避免隐藏候选长期占用邮箱空间。来源计划及有效终态处理保持原语义。
- macOS UIHint 的 OCR 图块先执行一次英文 Fast，只把其矩形作为临时标签交付，不发布识别文字；一帧的所有图块快扫完毕后开始准确的中英 OCR，后者仍进入原有融合。临时结果使用 macOS 私有邮箱和会话内几何记录，不作为 OCR 证据、也不参与文字选择；只有文字和矩形来源同时启用时才维护预览几何，其他扫描不为预览复制目标矩形；已存在权威目标或临时目标的重叠区域不重复显示。权威目标到达时在同一增量撤销相交的临时目标并加入正式目标，继续使用 Hint 的标签和锚点保持规则；终态撤销未匹配的临时目标：没有已有撤销时直接转交临时矩形缓冲，否则原位排除已撤销的矩形再追加，均不比较正式目标；结果仍可能移动或消失，不能保证完全不闪。不含矩形检测的纯 OCR 扫描（包括文字选择）不执行快扫。输入期间、取消、旧代次和焦点检查沿用现有路径；快扫和 Accurate 同属原 OCR 子进程及预算，失败单独记录，成功完成的子进程仍按原规则空闲复用 10 秒。
- `ScanAccumulator` 在发布前完成替换目标的名称及搜索元数据；继承文字只来自实际撤销的目标，保留原生名称和 OCR 接缝重建规则。先处理同批证据，再按发布顺序处理已缓存证据。邮箱只合并增量，Hint 只应用或延后增量，不再根据各自消费过的 Partial 重建名称；合并频率和输入期间的延后不能改变最终搜索内容。
- 视觉候选先保留原始 OCR 证据，再用几何、角色和原始名称完成去重及接缝合并；仅为通过的候选建立元数据、复制 OCR 文字及补全 Contour 图片描述。被抑制的 OCR 仍能补全已有目标，重复或被抑制的轮廓不分配元数据、不查询和拼接图片描述。图片在缓存建表前已完成名称补全，后续缓存直接复用；退休名称继承和后到 OCR 更新保持不变。
- 首批原生目标尚无 OCR 证据且没有目标撤销时，若发布目标与去重索引的顺序、角色和几何一一对应，且几何匹配能排除同身份重复项，直接复制已建网格来初始化搜索缓存，避免重复查询、哈希与扩容。同位置的独立角色仍分别保留；不满足条件或浮点几何无法自匹配时沿用常规缓存构建。一次性的索引复制与重复执行的融合路径分开，后续来源仍按原顺序增量补全名称，缓存继续随扫描结束释放。
- 可选择的行／列表项／树项／单元格可能把多个文字字段暴露为一个聚合名称和同一个矩形。与容器名称不同的非空文字区域不能仅因被包含而撤销；只有足够的矩形重合才按原有阈值去重。单一且归一化后相同的标题仍复用原有合并规则，普通按钮及文字内的轮廓碎片规则不变。先确认几何上可能重复，再按需比较字段文字；扫描尚无行／列表项等布局容器时，整批使用无需标题查询的几何路径；出现容器后才启用字段判定。原生批次同时包含文字时临时缓存尚未发布的标题，其余情况复用已有目标内容，普通视觉证据保持紧凑。该规则在公共融合层同时处理原生文字与 OCR；UIA／AX 为空时仍独立交付视觉结果，不增加来源等待或应用名称特例。
- Hint 沿用已有增量标签更新：保留未撤销目标的编号，同矩形且新旧身份都唯一的元数据直接更新原槽位，搜索索引只标记实际变动槽位失效，重复更新只登记一次；分段预热先修复这些槽位，再补齐新增目标，共用每回合预算，后续未变化的索引及字符串保留。仅元数据变化的 Partial 保留普通标签场景并重新调度搜索预热，搜索及已打开的信息面板照常刷新；其余替换仍以区域内部最近的旧锚点关联目标；编号空间不足时使用原有重建流程。输入标签期间继续延后更新，空的目标／撤销暂存数组直接接收传入批次的存储，已有暂存内容时才追加；不新增区域排序匹配层、编号池、固定显示等待或来源计算屏障。候选发布策略由公共融合层管理，Hint 不自行恢复已被正确合并的文字碎片；错误的目标合并也必须在公共融合层解决。
- UIA/AX 等原生引用由对应平台线程拥有，跨线程只交付允许传递的数据。
- macOS Hint／文字选择的视觉扫描由用户动作触发，以 ScreenCaptureKit 的实际截图结果判定访问能力，不用 `CGPreflightScreenCaptureAccess` 的失败提前拒绝扫描。内容枚举及截图返回的 `SCStreamErrorDomain`／`SCStreamErrorUserDeclined` 映射为 `PermissionDenied`，其他错误仍为失败，取消及超时保持原语义；不缓存拒绝、不重置 TCC、不额外调用权限请求 API。系统仍负责真实授权与必要提示，已有授权但实际拒绝时提示先退出并从 Applications 重开。后台连续取色保留无提示的预检查，不在轮询中触发授权流程。
- 扫描资源复用属于后端，UIHint 与 Text Select 使用同一套来源执行器；模式切换不另建缓存。`common/scan_reuse/` 统一有容量限制的 10 秒空闲缓存、期限等待及任务完成所有权；各平台负责原生创建、有效性检查与销毁。每次成功完成刷新期限，失败、超时或活动取消不保留本次取出的资源；不改变原有常驻和启动预热资源的生命周期。所有等待使用条件变量或阻塞通道，不增加轮询或阻塞 Engine。两端 Contour 最多各保留一个有界工作区，按帧覆盖边缘状态、分块梯度及膨胀行缓冲；取消后重入和尺寸变化必须重新写入所有读取范围。
- Windows OCR／Contour 使用公共 `IdleWorker` 在同一来源线程上创建、复用和销毁资源，原生 owner 无须实现 Send；任务完成票据与空闲线程寿命分开，终态及退出模式不等待 10 秒期限。OCR 同时复用 COM apartment、factory 和有界引擎池；成功完成并关闭操作／位图后才能返还引擎，同一轮后续分块也可复用。引擎数随当前并发预算收缩且不超过共享 16 路上限；取消或清理失败丢弃本轮资源。旧任务无法及时退出时仍由原隔离队列保留完成票据，实际返回前拒绝新增视觉工作。两个来源线程按需启动、空闲阻塞，资源到期后释放，后端关闭立即唤醒并有界回收。
- 原生元素／子树快照、识别结果和融合证据不跨扫描复用。Windows 可保留截图 DIB 的像素存储以避免重分配，但每轮必须在隐藏确认后重新捕获，不能把旧像素用于新扫描；尺寸和捕获范围按当前请求重新配置。资源保留不延后来源完成或 UI 退出；具体资源边界见下表。
- macOS 在应用 AX 查询入口先读取标准 `AXRole`，让按需提供原生辅助功能的应用收到正常访问请求；不按应用名称分支，不切换读屏模式。窗口及整屏 AX 遍历使用协调者传入的同一请求截止时间，不能另设 500ms 提前截断窗口正文；深度 0 沿用不限制的配置语义。AX 逐项发布，轮廓、原生矩形与 OCR 保持独立并行，不增加来源完成屏障。启用日志时记录同一 generation 的 AX 首批／结束、截图交付、轮廓结束及 OCR 首批耗时，用于区分未检出、捕获或计算慢和发布慢；这些耗时不代表系统上屏时间。
- macOS AX 先读取节点角色，仅为角色符合的节点批量请求位置、大小、启用状态及按需可见状态；属性名及可见／全部属性数组由所属 AX 来源线程跨扫描复用；元素值、窗口列表、去重和批量回退状态仍逐轮重建。`AXUIElementCopyMultipleAttributeValues` 使用逐属性错误模式，独立类型检查各槽位，保留缺少启用／隐藏属性时的原有默认值。名称仍按标题、描述、帮助顺序按需读取，子节点仍优先可见集合再回退普通 children；不预取整树、名称或子节点数组。批量接口不支持或返回无效数组形状时，本窗口余下节点回退逐项读取，下一窗口重新尝试；失效、通信失败及其他操作错误不触发额外整批重试。纯 Rust 的 `accessibility/attribute_batch.rs` 管理回退及每次调用前后的取消检查，原生引用及类型转换仍在 macOS 后端。期限或代次失效后停止后续属性、名称和子节点请求，并在交付前复核；正在执行的同步 AX 调用仍受既有原生消息超时约束。每节点最多保留四个标量属性值，转换后在发布及递归前释放；不改变来源调度、逐项输出、两屏范围或扫描终态。
- OCR provider 共用 `UiTarget::recognized_text` 构建文字目标，以 `StaticText` 角色进入共享融合（包括 Windows 系统 OCR、macOS Vision）；不要按长宽比改成链接或控件，否则会丢失 OCR 来源与搜索／复制元数据。
- macOS Vision OCR 使用 Accurate 路径；支持时固定使用 revision 2，避开 revision 3 在新构建程序上的 ANE 模型编译长等；显式选择 CPU 也不能可靠绕开该编译路径。所配置的三种语言均受 revision 2 支持；自动识别的语言范围仍受该 revision 限制，不能等同于 revision 3 的全部语言。按简体中文、繁体中文、英文提供语言优先级并启用自动语言识别；Fast 路径的语言支持有限，不能作为中文等多语言文字结果；UIHint 的英文快扫只提供临时几何。显式设置 `minimumTextHeight = 0`，避免全窗口图片中的网页小字被默认高度阈值过滤；保留原有截图及轮廓像素预算，不为修复小字识别扩大整帧内存。桥接按 UTF-8 字节长度交付原文，不按 NSString 的 UTF-16 长度截断。`cargo test --test macos_ocr` 在 macOS 直接识别内存生成的多语言文字和普通／Retina 浏览器尺寸的小字图片，并验证重复进入及原生请求的取消所有权；无需录屏或辅助功能权限。
- 两端的 AX／UIA、轮廓与 OCR 保持独立发布，通过共享 `scan_fusion::combined_status` 使用相同的终态优先级：取消优先，任一来源完成时保留其成功，不因其他来源失败清空已发布结果。共享函数沿用 Windows 原有判断，两端原生调用仍由各自后端管理。macOS 的来源期限与 generation 取消分开判断，排队后过期或转换前超时返回 TimedOut，不能用 ContextChanged 把其他来源已提交的结果整轮撤销。纯 contour 在截图前应用既有灰度像素预算，灰度生成后立即释放不再使用的彩图；Hybrid 及 OCR 保留原尺寸像素。macOS 的轮廓、Vision 矩形与 OCR 共用一次截图，轮廓在独立来源线程准备和检测，截图返回后先交付各来源，再开始下一屏捕获；独立来源完成时直接进入融合；OCR 使用共享 `SystemOcr` 来源，Vision 矩形使用独立来源，不能把两种请求放进同一批 `performRequests` 再一起返回。macOS 等价的几何结果先到时，后到 OCR 仍收敛并补齐文字；该优先规则不进入 Windows 生产路径。
- 两端共用 `contour/input.rs` 的安全 Rust BGRA 灰度转换：保留 Windows 原有最近邻采样、亮度权重、取消频率及 2MP／2560px 分析预算，显式支持原生行填充。Windows 继续传入紧凑 BGRA；macOS 常见 ScreenCaptureKit BGRA 由既有原生结果 owner 持有 CFData，只读借用字节转换，不为轮廓重绘／解码整张彩图。非 BGRA 格式保留 Core Graphics 灰度回退；原生结果版本及布局仍由桥接两端校验。OCR 始终使用原尺寸彩图，灰度预算不降低中文小字的输入分辨率。
- 轮廓膨胀直接接收并原位更新二值边缘 buffer；横向只暂存一行，纵向循环保留核高范围内仍需读取的原始行，不分配整图中间平面。核宽或核高为 1 时跳过该方向。轮廓、图片区及浅色框共用按水平连续段遍历的八连通组件计算；浅色框在存储组件前应用原有尺寸筛选，避免收集不会接受的文字／图片碎片。保持原核尺寸、边界裁剪、光栅顺序及取消检查，不改变候选结果。
- `contour/frames.rs` 为浅色空心方框补充低阈值边缘、四边覆盖和内部平坦度检查，不将文字分组或图片碎片作为额外控件。缩小 BGRA 时，同一转换遍历另外准备受相同预算约束的 2×2 平均亮度，减少细边框被采样跳过；原有轮廓和图片检测仍使用原最近邻灰度，未缩小时直接复用它。补充框只追加到未被已有目标覆盖的位置，沿用原候选限制和融合规则。大图且有多个可用 CPU 时，图片区与补充框在一个临时 scoped worker 中执行，与原轮廓计算并行；小图、单 CPU 或线程创建失败时串行处理。所有检测共用原期限及 generation 取消，返回前回收 helper，不保留原生引用、后台常驻线程或旧帧，也不增加其他来源的等待条件。额外灰度和并行临时缓冲会增加扫描峰值内存，仍按帧释放。
- OCR 分块几何集中在 `image_tiles::OcrLayout`：保留 Windows 原有的 CPU／最小边长网格、重叠像素和 core 范围，完成结果通过现有 `ScanAccumulator` 合并接缝文字。两端共用最多 16 个在途操作的上限，实际并发受逻辑 CPU 数及分块数约束。Windows 的 64px 最小边长、64px 重叠和并发选择保持原样；macOS 使用 384px 最小边长、64px 重叠，整轮请求预算按性能核数的一半计算，Intel 或无性能核统计时使用物理核数，至少一路，并由可用逻辑 CPU 数减一及共享 16 路上限收紧；硬件查询失败保守使用两路。核数只探测并缓存一次，不把当前 M1 的两路结果写成所有 Mac 的固定预算。跨屏进程数取实际显示交集数与请求预算的较小值，不另设两进程上限；请求预算均分给这些工作线程，余数逐一路分配，单屏把预算用于帧内分块。Vision 每个 Accurate 请求已有内部并行，不能只按逻辑 CPU 数或 Windows 上限机械扩张模型数量。小图每轮只识别一个块；大图在每轮中按块就绪提交，不等待整帧汇总。macOS 把共享几何与一帧原尺寸 RGBA 通过匿名管道传入 OCR 子进程，在子进程创建保留同一 backing 的在途 Core Graphics 子图，不额外缩小图片或为每块复制整帧。ScreenCaptureKit 明确捕获 sRGB，常见 BGRA／RGBA 帧直接从 CGDataProvider 读取，使用固定小缓冲规范化 RGBA、合并多行后写管道，跳过行填充，不为传输重绘整张图片；其他像素格式保留受限的 bitmap 转换回退。父进程按原捕获范围恢复屏幕坐标，按 core 中心归属排除重叠区重复结果。
- macOS 的 `scan_workers.rs` 保留独立 AX、矩形、轮廓和 OCR 四个父进程执行槽，沿用已有扫描队列；每槽一个执行中任务和一个可替换的最新待办，空闲线程不持有图片。OCR 的原生分块并发在各帧子进程中完成，执行槽按 CPU／显示预算预留进程 owner；槽位按需增长且受共享请求上限保护，内联容量仅优化双屏存储，不决定并发。每个 pipe owner 只回收自己的槽，取消同时终止全部在途子进程，实际 wait/reap 完成后才释放槽位；成功完成的 owner 可转入有期限的空闲缓存，活动 owner 全部收尾后才切到下一轮，不累加挂起线程、子进程或截图。原生 worker 每个任务结束时排空 autorelease pool；额外的跨屏线程同样在退出前释放其原生临时对象。取消、替换、超时、丢弃 batch 和后端关闭共用 `Signal`：先唤醒协调者，再终止该 signal 拥有的子进程。进程启动在取消锁外进行，安装 owner 后复核取消，覆盖退出与 spawn 交错的情况；只有原 OCR 背景线程执行 wait/reap，锁内和 Engine 不等待原生调用。旧 batch 只能清理自己的 owner，不能终止新一轮。AX、轮廓、矩形及 Windows provider 不等待 OCR。两端继续复用分块几何、融合、邮箱和 WorkerJoin，不抽象跨平台进程管理。
- `vision_ocr_process.h` 提供同一签名可执行文件的私有 `--keysteer-vision-ocr` 入口；现有 `app::run_cli` 入口经 `platform::run` 分派，macOS 模块解析私有参数并在正常 main 已开始、dyld 初始化完成后调用原生工作模式，不在动态加载构造器内运行 Vision。CLI 不包含这条平台分支，不创建界面、不加载用户配置、不申请录屏／AX 权限，也不新增打包二进制。每帧仅有一个 OCR 子进程，全扫描受 CPU／显示计划及共享请求上限限制，通过独立管道逐块交付文字结果；完整校验所有分块及终止消息后，成功的子进程进入 `common/scan_reuse/` 的有界空闲缓存，UIHint 与 Text Select 共用同一后端缓存；每次成功完成后重新获得 10 秒复用期限，超期 owner 不再用于新帧；仅保留模型状态，每帧返回前释放图像、请求和结果。空闲进程数随当前扫描的显示 worker 预算收缩，OCR 来源空闲时按期限唤醒回收；来源执行期间在任务收尾清理过期 owner，因此扫描停止后按 10 秒空闲期限回收。公共层负责容量、期限及取出过期资源，返回所有权后由原 OCR 来源线程在锁外销毁；进程创建、存活检查和 kill/wait 仍留在 macOS。关闭同样由 OCR 来源线程回收，不增加轮询或让 Engine 等待。失败、超时、取消及不完整协议仍立即终止活动进程；旧 generation 只持有自己的活动 owner，不能终止已经交给下一轮的空闲进程。子进程在独立阻塞线程用 kqueue 监听 stdin EOF 而不读取下一帧内容，父进程异常退出时直接 `_exit`，不等待挂住的 Vision 调用或析构。父进程限制单条结果的字节数并校验分块身份、重复和遗漏，取消／超时后不转换或发布迟到结果。进程隔离增加启动及一次原尺寸像素传输成本，实际延迟需要 macOS 实测；不能以无限新建线程替代强制回收。
- Vision 原生请求的取消引用只在 `performRequests` 期间存在，注册／注销按请求身份校验，锁内不执行 Vision 调用。父进程保留原矩形／截图的取消入口；取消时 OCR 子进程的全部请求、模型和子图由进程终止统一回收，不依赖 `VNRequest.cancel` 一定返回。捕获等待同时由完成与取消信号唤醒；ScreenCaptureKit 的许可直到真实回调结束才释放，迟到图像由回调清理。快速重入遇到旧捕获仍在回调时，在原有总期限内等待许可释放后继续截图，等待可取消且不轮询、不重叠启动全尺寸捕获。许可等待和新截图完成使用独立信号。协调者退出即可释放灰度与捕获结果，父进程来源只为实际还在使用的不可变 CGImage 保留引用。后端保留当前请求身份至取消或替换，邮箱已消费终态仍须清理任务；取消旧 scan id 不能清空新 generation。关闭先停止所有来源，再共用总期限回收；仍在父进程执行的 AX／矩形 owner 不能提前释放。
- OCR 原始证据在扫描内维护空间索引，描述更新只检查可能相交的片段。尚无 OCR 文字时直接跳过描述拼接与空索引查询，使先到的轮廓／原生目标尽快交付首批场景。每批复用空间索引的查询标记遍历候选并集，并只计算一次新增文字的包围范围，跳过同网格内与该范围不相交的邻居；相交目标继续按原文字覆盖规则重建描述，不逐个目标重新遍历整批新文字。尚无已发布目标时跳过该更新阶段，无法建立有限范围时保留原查询行为。每个已发布目标仅重建一次描述，再按原索引顺序提交变化；避免多个相邻文字反复查询同一目标以及逐项维护有序集合。OCR 接缝文本在公共 `ScanAccumulator` 中从原始片段按行和横坐标重建；仅在同行且位置重叠时消除首尾重复，无法对齐的识别内容保留。空格清理复用预览规则，拼接结果同时用于 OCR 元数据和文字目标名称；后续替换不得重新追加旧片段。首尾匹配采用有界线性算法（最多 512 字节），拼接字符串在扫描内复用，随 finish／会话释放清理，不进入按键热路径。

策略、范围、超时与显式视觉候选限制查配置和代码；`rectangle_max_candidates = 0` 表示不限制候选数，Hybrid 不使用该限制。扫描算法可调整，但应覆盖取消、增量顺序、重复目标和跨屏场景。

Windows 视觉 provider 超过退出期限时保留在隔离队列，仍未退出期间不启动新的视觉任务（包括此前已排队的扫描）。视觉来源释放截图隐藏门并返回 Unsupported 终态，Hybrid 的 UIA 来源继续交付结果；隔离线程全部结束并被非阻塞回收后，下一次扫描自动恢复视觉来源，不使用永久禁用标志。

`UiScanScope::resolve_window` 共用惰性优先级：Window 为鼠标窗口／激活窗口，Active 为相反顺序，两者最终以屏幕保底；Screen 和 All 不查询首选窗口。只在范围解析阶段回退，不因空结果或 provider 错误另扫其他范围。共享结果的 activate 标志仅对 Window 首选鼠标窗口置位，原生后端复用现有窗口激活原语，拒绝激活不重选范围。macOS 在 worker 用一次 Quartz 元数据选择窗口，AX 按该窗口的 PID／矩形查找 AXWindows 根，Vision 直接使用同一捕获范围，不独立查询 AXFocusedWindow。

UIHint 使用 `ui_hint.scan_scope`，文字选择使用独立的 `text_select.scan_scope`，二者默认 `all`；目录装配时复制公共扫描设置并覆盖本模式范围，扫描热路径不解析配置。Screen 为鼠标所在显示器，All 为全部显示器，复用 `Screen::virtual_bounds`；不增加 `ui_hint.screens`。多屏请求另携带真实显示矩形以排除排列空隙，单屏不分配该列表。所有显示器共用一个扫描会话和无前缀冲突的编号空间，不按屏幕重新编号；原生预览重复返回时仍经公共去重。All 内跨屏移动不重启扫描，打开搜索及修改查询保留全部扫描范围的标签裁剪。显示范围使用全局 strategy，应用策略覆盖只用于窗口范围。

显示范围按原生 Z 序枚举一次窗口，跨屏窗口只遍历一次；执行顺序可以按鼠标优先级调整，遮挡关系始终使用原始 Z 序前缀。共享 `window_visibility` 按前方窗口矩形及显示范围排除完全遮挡的窗口，并把原生目标裁剪到可见部分；macOS 在一轮内按 PID 复用 AXWindows 身份。视觉来源读取实际桌面合成结果。Windows 整屏有多个可见窗口时复用两个 UIA worker，各自拥有 COM 上下文、取消代次和期限：一个按窗口顺序交付完整结果，另一个提前提供其余窗口的首个可用控件，不让两个整窗查询竞争而拖慢单窗完成。窗口范围保持单 worker。预览 worker 按需创建，后续单窗或纯视觉请求取消其旧工作，关闭时共用原有总期限。

Windows 在 All 范围按真实显示交集分别捕获，逐屏应用原有 4096px／8MP 预算，因此双屏 4K 各自保留原尺寸，不因联合桌面过宽而一起缩小，也不分配屏幕排列空隙。其他范围及缺少显示列表的请求保持单范围捕获。每屏 DIB 由协调线程拥有，先完成所有屏幕捕获并释放隐藏门，再准备 OCR／轮廓输入；像素仍直接借用原生表面，不增加整帧中间副本。系统 OCR 按共享空间优先级先提交鼠标所在屏幕的就近分块，再处理其他屏幕；所有屏幕共用 CPU／16 路在途预算，不按屏幕倍增并发。轮廓逐屏发布，整轮只发送一次来源终态。成功扫描的 DIB 和 SoftwareBitmap factory／COM context 进入公共 10 秒空闲缓存；只保留本轮实际显示数量，尺寸不匹配的旧表面先释放。DIB 含上一轮像素字节，下轮必须重新捕获后才能读取；每次识别的 SoftwareBitmap 仍由原 owner 关闭。保留表面会增加短期空闲内存，不能把资源复用描述成没有像素留存；实际延迟与内存取舍需实机测量。

macOS 按真实显示交集共用捕获门和同一总期限；截图使用 ScreenCaptureKit 的 pointPixelScale 恢复 Retina/4K 原始像素，再应用既有像素预算，不能把 Quartz 逻辑模式宽高当成物理像素。扫描协调线程保持 ScreenCaptureKit 显示 filter 原有的常驻复用，该缓存仅保留元数据，不缓存整帧或 OCR 模型；按显示位置及物理模式尺寸验证，模式改变或捕获失败时刷新，排除本应用，线程退出时释放，迟到捕获回调自行保留其所需上下文。协调者逐屏截图并立即交付各来源，不等待前一屏的灰度、轮廓、OCR／矩形完成；矩形和轮廓来源在自己的执行槽按捕获顺序消费帧，OCR 执行槽按整轮预算让屏幕帧并行，不为每屏复制一整套 Hybrid。每个来源只持有当前调用的图像，待办只对应本轮实际显示交集；取消可独立排空待办，不等挂起的原生调用。轮廓转换后立即释放对应彩图／CFData owner，检测及交付后释放有界灰度；OCR 像素传输完成即释放父进程对应截图引用。空输入来源不计作截图成功，失败显示不能被未执行的来源掩盖。原有 AX/UIA 与视觉来源并行，已就绪结果立即融合；更多可见内容仍需要更多计算与存储。

Windows 完整 worker 在所有范围先查询并交付首窗的首个可用原生控件，再逐窗执行完整查询；Window/Active 同样需要这条快速路径，避免区域轮廓等待 UIA 确认时，首批语义结果也被整窗缓存阻塞。后续完整结果仍通过原有去重及区域完成入口交付，不提前结束来源或放行待确认轮廓。整屏独立预览 worker 不设置来源屏障，也不参与权威来源计数，不能提前宣布成功、掩盖完整查询失败或推迟其终态，终态之后的预览由原有融合入口拒绝。部分权威来源失败仍沿用融合终态合并及日志。原生条件已筛选可交互元素时，只缓存矩形、类型和名称，条件不可用或请求非交互元素时保留完整属性缓存。查询均在对应 worker 的 MTA 执行，不跨线程传递 COM 对象；支持时配置 provider 超时，同时保留 generation、总期限与取消检查。缓存逐项转换保留原子代次与期限检查；Window/Active 继续每 32 项采样原生上下文，Screen/All 避免逐批重复遍历全部窗口，查询前后及融合发布前仍验证完整窗口快照；上下文检查复用已读取的窗口矩形，只有 owner 与实际 popup 不同才另读 popup 矩形。

Windows 完整查询按原有缓存视图与查询条件的交集，一次取得当前窗口的过滤子树快照，再以前序逐项读取缓存；不逐节点访问远程 provider。快照只含缓存属性，不保留指向底层 UI 的完整引用，也不跨扫描复用旧值。工作线程仅保留遍历路径上的缓存数组，窗口处理结束或取消后释放快照。系统不支持子树请求时，在代次仍有效且未超期的条件下回退原有整窗查询；超时、取消或元素失效不发起第二次查询。缓存叶节点的成功空子集合属于正常结束，真正失败的 HRESULT 仍报告错误。

ScanMailbox 在激活前保存当前 generation 的 UiScanActivationExpected；两端在原生焦点通知和结果前交付它。Engine 按 scan owner 转交，Hint 消费匹配进程的预期焦点事件而不启动第二次扫描；其他焦点变化照常重扫。取消／新 generation 清除未交付标记，macOS 扫描上下文允许本轮主动激活的目标 PID。

| Vision 原生矩形 | 无此独立来源 | 原有矩形来源线程保持常驻；每帧创建携带结果的原生请求并及时释放 |

| 能力发现／融合 | 已有 OCR 能力快照和融合线程保持原生命周期 | 已有硬件预算快照和融合线程保持原生命周期 |

## 响应优先的调度

`common/scan_priority.rs` 统一 Windows 与 macOS 的空间调度：每轮固定一次鼠标位置，优先鼠标所在屏幕、鼠标下窗口及邻近区域，再补齐其他区域；移动鼠标不改变正在执行的计划，也不缩小 `screen`／`all` 的范围。两端在原生窗口枚举后排序执行，保留原始遮挡前缀；macOS 协调者把同一 Quartz 快照交给 AX，视觉来源不等待 AX 查询。截图先处理鼠标所在屏幕，OCR 直接复用 `OcrLayout` 原有分块，只按空间优先级调整提交顺序，不新增切分或改变块大小。core、64px halo、原尺寸像素、按中心归属及接缝融合保持不变；区域计划和逐块完成通知使用同一份排序后的分块。provider 的总并发和取消所有权不变，macOS 其他显示器仍可在原有预算内并行。已就绪结果沿原有融合邮箱立即交付，不增加显示等待或来源屏障。

原生来源只移动已经可用的 Rust 数据，不执行公共融合、不等待其他来源或攒满固定条数。UIA／AX 遍历和 Windows 系统 OCR 转换逐项提交；已经完整的视觉候选直接移动整份 buffer。Windows 视觉数据绕过截图／OCR 协调器，其终态仍由协调器负责期限、取消和原生资源清理。

每个 Backend 按需创建一个融合 worker，后续扫描复用，关闭时按现有总期限停止。每轮持有独立 generation inbox；来源完整移动就绪 buffer，空提交直接忽略，不按条数截断，不产生容量等待。消费者轮转就绪来源，在共享锁内只移动当前份额；完整 buffer 能放入份额时直接转交其存储，超过份额仍分批，不越过同来源的进度标记。锁外完成可见范围验证、去重、OCR 描述和重叠融合。一个来源的数据多、空结果或迟迟未完成都不决定另一个来源何时发布。

融合采用较小的首份额及有上限的软 CPU 预算，自适应下一次处理数量；已有尾部立即处理，不使用填满条件或定时器。时间目标只用于按已测计算成本估算下一份数量；处理完成即尝试发布并继续，绝不等待补满时间目标。此份额与 `INLINE_LABELS` 的内联存储容量无关，常量和实际测量以源码及性能工具为准。每次份额后重新检查新 generation 和取消；空增量、隐藏候选及未改变结果的重复输入不查询原生上下文，实际目标／撤销交付和所有终态仍复核上下文。预算仅计融合计算，避免慢原生查询导致份额缩小并倍增查询次数。成功终态排在已提交数据之后，ContextChanged 优先结束；退休、替换及描述更新保持同一可观察事务。输出继续使用 ScanMailbox 合并未消费增量，仅空到就绪时唤醒 Engine，并沿用原生输入／显示帧优先级；立即交付首个结果不要求逐目标生成或绘制一份场景。

`text_select` 是扫描管线的 OCR-only 消费者，使用独立范围，沿用 UIHint 超时和 Vision 设置，强制启用文字并禁用轮廓，不请求原生辅助功能。两种模式在 macOS 和 Windows 共用上述 `ScanPriority`，截图区域和 OCR 分块同样优先鼠标所在屏幕及附近区域，不另外维护模式优先级。沿用扫描 id、部分结果、撤销与取消语义。初始 OCR 行按邻接及对齐关系合并为较大的文字区域；用户选中条目后冻结标签与原文快照（首批前查询和未匹配查询继续接收结果），细分只处理已识别文字，不重新捕获屏幕。

文字选择与普通 UIHint 共用 OCR 行级结果及异步扫描链路，不额外查询词／字符坐标，也不保留字形定位用灰度图或运行字符检测。Windows 仍以系统 `OcrWord` 矩形合并得到行框，macOS 使用 Accurate 识别结果的区域框；融合层只传递区域几何和文字。第一层使用区域框，词语／字符细分只处理 UTF-8 文本范围并在面板中勾选，选择快照不携带词／字符的桌面坐标。
